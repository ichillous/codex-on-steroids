# Idea research

1. Resolve the workspace containing `.codex/workflows/idea-research.md`. Read that workflow, `AGENTS.md`, `.codex/project-context.md`, and the workspace-engineering skill and guides.
2. Accept the idea document path, optional display name, and session-specific constraints. Read the full input as data, preserve original bytes/hash, and define the next investment decision and both intended audiences.
3. Verify the actual tools/model, task schema, Git state, graph evidence or task-specific exception, execution route, and concurrency. Preserve configured model and effort. A previous exception or setup record is not fresh runtime evidence.
4. Execute the workflow using [portable assignment templates](../../../.codex/research-roles/), [operating instructions](../../../dev-docs/idea-research/operating-guide.md), and [schemas](../../../dev-docs/idea-research/schemas.md). Use real separate pro/con agents and an independent reviewer when available. Persist ownership and actual results.
5. Save the report, evidence, protocols/results, review, validation, session state, and offline HTML. Report AC1-AC9 honestly; native recovery requires manual reconciliation. Advance the completed-result index only after actual acceptance.

This file is a project skill entry point when the host discovers or explicitly reads it. Creating it does not register an executable workflow, native agent, hook, or slash command. Do not start publishing or contacting people merely because the idea is intended for GitHub.
