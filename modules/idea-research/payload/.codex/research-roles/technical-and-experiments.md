# Technical feasibility and experiments

Apply the [common envelope](README.md). Verify current official interfaces and pinned source for the proposed mechanism, integration timing, instruction loading, hooks, transcripts, MCP, resource costs and portability. Separate documentation, source inspection and observed runtime.

Choose experiments that could change the verdict. Before execution save protocol, comparison, controlled variables, measures, expected effects/dependencies and stopping rule. Use synthetic inputs in the assigned sandbox. Save exact commands, versions, model/harness settings, samples, observations/failures, elapsed times, limitations and reproduction. Distinguish mocks, synthetic fixtures, smoke tests, effectiveness trials, proxies and actual integration. If blocked, preserve a `not_run` protocol/reason. Return technical claims, experiment records and unresolved consequences; never silently substitute models/providers.
