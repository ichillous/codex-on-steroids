# Portable research assignments

These files are assignment templates supplied to native workers, not registered native role IDs or engineering-coordinator specialist IDs. Use the host's actually supported agent type and preserve configured model/effort. The engineering runner's schema is separate; do not invent a `researcher` or `advocate` specialist ID there.

Every assignment must fill this common envelope:

- Objective, target audience and decision being informed.
- Shared brief path, full controlling requirements, input/evidence paths and relevant claim IDs.
- Specific bounded questions and evidence standard (fact/inference/assumption/unknown).
- Permitted reads/tools/network/effects; exact owned output file and optional experiment sandbox.
- Other agents are working in the workspace. Preserve their files; no shared writers, unrelated edits, recursive delegation, or another coordinator.
- Initial pro/con independence: do not read the opposing initial output until the coordinator explicitly starts rebuttal.
- Expected output: author/worker identity, assignment, actual work and timestamps, findings tied to claims and sources/experiments, contrary evidence, confidence/scope, unknowns, recommended follow-up and stopping reason. Include source fields from the schema; the coordinator assigns canonical IDs and integrates shared records.
- Stopping conditions: answered bounded questions, repeated evidence with no consequential gain, unavailable required access, denied effects, or agreed limit. Preserve partial findings and mark unfinished work.

The coordinator owns shared sources/claims/session/report/index. Workers return results or write only their assigned files. Experimental writers use separate sandboxes. A worker's claimed execution must have attributable output or runtime evidence.
